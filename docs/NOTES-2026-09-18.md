# EXALTED Terminal 77 — build log 2026-09-18

## New surface: the in-game browser Bible site (redscript)
Port of the KJV reader into the **in-game browser** via the **Browser
Extension Framework** (Nexus mod 10038). This is a second, independent
surface over the same JSON dataset; the CET terminal keeps working without
it. No CET, no Lua — pure redscript (`r6/scripts/EXALTED/`).

## What was built
- `internet/EXALTED/Site.reds` — module `ExaltedSite`: site listener
  (`ExaltedSiteListener extends BrowserEventsListener`), router, and the
  inkWidget page builders.
  - Address `NETdir://exalted.terminal`, shortName `Exalted Terminal 77`,
    icon `zetatech1` (base icons atlas).
  - Routes: `/` home, `/about`, `/books[/<pg>]` (20/page), `/b/<short>[/<pg>]`
    chapter list (24/page), `/r/<short>/<ch>:<vp>` reader (10 verses/page).
  - Widget names carry the destination address; one shared click callback
    routes via `NameToString(w.GetName())` → `LoadPageByAddress`.
  - Fallback `@if(!ModuleExists("BrowserExtension.System"))` no-op class so
    the file still compiles without the framework.
  - `@addField(BrowserGameController)` + `@wrapMethod` OnInitialize/
    OnUninitialize to register/unregister the listener.
- `scripts/gen-exalted-reds.py` — turns `cet/EXALTED/data` (book JSON) into
  redscript string modules: 66 `ExaltedBookNN.reds` + `ExaltedData.reds`.

## Generated data encoding
Token scheme inside a chapter string:
- `{|}` verse separator → split gives `[vnum, body, vnum, body, …]`
- `{~}` line separator (exporter paragraph breaks)
- `{r}`…`{/r}` red-letter wrapper for the words of Christ
- wrap width 88 (was 76); literal `{`,`}`,`~` are rejected by the generator
Counts: 66 books / 1189 chapters / 31102 verses / 2028 red-letter verses =
67 data files + Site.reds (68 total). Largest literal 15789 chars
(Psalm 119) — fits redscript's String. 1390 string literals total.
Shorts verified against `books.json` = 0 mismatches.

## Bugs found and fixed Sep 18
1. **Generator compile error:** `ExaltedChapterText` data cases passed `c`
   but the parameter is `chapter` → fixed to `ExaltedBookNNChapter(chapter)`.
2. **Missing imports:** `ExaltedData` references cross-module book functions
   but never imported them → added `import ExaltedBook01..66 .*` (66 lines).
3. **Dead links:** `inkText` links need `SetInteractive(true)` before
   `RegisterToCallback` or hover/click never fire → added in `EXAL_Link`.
   (Confirmed required in the framework's own `BrowserController`.)
4. **Cosmetic:** book rail label said "THE OLD TESTAMENT" while listing all
   66 books → "THE LIBRARY".

## Reader layout pass (Sep 18→19, FINAL)
User feedback: reading area should fill right/bottom; menus centered; header
stays top-left; and (final request) the bottom of the page must not move when
flipping pages.

- Adaptive detour (measure `page_content`, re-wrap lines to measured width)
  was implemented but showed ZERO change in game — fully reverted.
- Static value bump in `internet/EXALTED/Site.reds` only:
  - lines per page: **6 → 10**, body text: **42 → 46**, verse numbers:
    **40 → 44**, "Page x of y": **44 → 48**, reader nav links: **40 → 44**.
  - Header stays 72 top-left; menu/buttons unchanged (centered via EXAL_Link).
  - Generated data re-encoded with **wrap 88** (browser-only; counts unchanged:
    66/1189/31102/2028).
- Container resize attempts (Sep 19): `page_content` 1850 → 2200, then its
  parent, then a 6-hop ancestor walk calling `ExaltedResizeContent` (extension
  on `BrowserController`/`BrowserGameController`) — **NO visible effect in
  game**; the framework re-anchors the page to `Fill`. User declared resizing
  dead; the whole resize extension chain was REMOVED during the publish
  cleanup (dead code — no call sites remain).
- Compile fixes found via in-game `redscript_rCURRENT.log`:
  - `Cast<Int32>(ArraySize(...))` → NO_MATCHING_OVERLOAD — replaced with a
    plain `Int32` counter loop (`while i < ArraySize(...)`).
  - `LogChannel(...)` → UNRESOLVED_FN — removed.
- **FINAL shipped behavior:** the reader footer (divider + page/chapter nav)
  is pinned to the canvas bottom (`inkVerticalPanel` anchored `BottomCenter`,
  bottom margin 40) instead of flowing under the text, so the bottom edge
  stays fixed across pages regardless of per-page content height.
