# EXALTED Terminal 77 — build log 2026-09-16

## Final architecture (as shipped)
Port of the EXALTED Terminal Bible reader into Cyberpunk 2077 as a **CET
Lua mod**. **Pure Lua**: the King James Bible ships as clean JSON in
`<mod>/data/` and is read directly with CET's built-in `json.decode` +
mod-relative `io.open`. No bridge binary, no host process, no network.

Scope decisions (user-confirmed):
1. A hotkey **terminal** (THE BOOK surface was split out and parked at
   `cet/book-prototype/ui/book.lua` — not shipped).
2. **Isolated game copy** of the data (not `~/.biblelearn`).
3. **New standalone repo** at `~/cyberpunk-exalted/`.

## Data pipeline (Go exporter in the biblelearn repo, uncommitted)
- `cmd/bibleexport/main.go` — USFM → JSON exporter:
  - 66 canonical books, skips deuterocanon (`\id TOB`… interleaved between
    MAL and MAT in the source USFM).
  - Inline `\id` recovery: 65 lines carry a verse + the next book's `\id` at
    line end (the MAL→TOB case is the critical one — see bug below).
  - Red-letter: `\wj ... \wj*` → `segs[]` with `r=true` on the quoted span;
    `text` stays clean, no markup.
  - Cleaning order (matters): footnote → strong codes → close tags
    (`\\(?:\+[a-zA-Z0-9]+|[a-zA-Z0-9]+)\*` BEFORE `reArg`) → open tags
    (`\\(?:\+[a-zA-Z0-9]+|[a-zA-Z0-9]+)\s?`) → whitespace collapse; then
    `strings.TrimSpace` per segment; same-color adjacent segments merged with
    a space; `segsText` joins parts with `" "`.
  - Output: `data/books.json` (n, name, short, chapters, **verses**),
    `data/kjv/<n>.json`, `data/terms.json` (term → count, desc-sorted).
- **Malachi 4 fix:** first pass lost all of MAL 4 because non-canonical
  `\id TOB` is inlined at the end of MAL 4:6; the skip branch used to clear
  `curVerses` without flushing the open chapter. Fix: non-canonical branch
  calls `handleLine(head)` + `addChapter()` before `skip = true`.
- **Clean-text fix:** bridge-era `cleanText` left `+add`/`was*` artifacts;
  the choice is byte-identity vs cleaner text — **cleaner text** ships.

## Lua data layer (lib/cache.lua)
- Loads `data/books.json` at init → canon; per-book `data/kjv/<n>.json`
  decoded once and cached (`booksData`); chapters memo `"book:chapter"`.
- Persistence (mod-folder-relative): `exalted_bookmark.json`,
  `exalted_notes.json`, `exalted_notes_trash.json`, `exalted_memory.json`.
- Notes: add = upsert by ref, remove **moves to trash** (recoverable — the
  NO-DELETE rule).
- Memory: SM-2 deck mirroring `store.ScheduleNext` exactly
  (state 0 new → state 1 due+10m; state 1 q0 ease−0.15 due+10m else reps+1
  interval=1 state=2 due+24h; state 2 q0 ease−0.20 state=1 due+10m else ease
  clamp formula, reps 0→1d / 1→6d / else interval*ease (q≥4) or *1.2, reps+1,
  due=now+interval*86400).
- Search: frame-stepped background index (2 books/frame via `cache.poll` in
  `on_draw`) so search is fast without a frame hitch; substring over all
  tokens, limit 24; results `{book, chapter, verse, bookname, text}`.
- Terms: lazy decode of `terms.json`, prefix match, top 12.
- Ops keep the bridge-era shape (boot/getBooks/chapter/read/search/terms/…)
  with synchronous callbacks so `ui/terminal.lua` needed only surface tweaks.

## Root cause: terminal was "invisible" (why it never launched)
- The mod loaded and the hotkey bound, but the window never appeared. Cause:
  `init.lua` used an **`app.on_draw` method** (returned-table pattern). CET
  1.37.1 does **not** dispatch an app-table draw method — verified in the CET
  source: `ScriptContext::TriggerOnDraw()` runs only the callback stored by
  `registerForEvent("onDraw", ...)`; the returned table is used **only** by
  `GetMod()` for inter-mod communication (`ScriptStore::GetMod` →
  `GetRootObject`). So `terminal.visible` toggled but `terminal.draw()` was
  never called.
- **Fix (`init.lua`):** draw through `registerForEvent("onDraw", …)` and init
  through `registerForEvent("onInit", …)`; the returned table is now just
  name/version metadata. (Both working installed mods — nativeInteractions,
  CourierJobs — use `registerForEvent("onDraw", …)`.)
- `os.clock`/`os.time`/`os.date`/`os.difftime` are whitelisted in CET's
  sandbox (`LuaSandbox.cpp`), so the `on_draw` preloader is safe.
- Notes: CET auto-creates `db.sqlite3` and `<ModName>.log` inside every mod
  folder (`LuaSandbox.cpp`), so those 0-byte files are **normal CET
  artifacts**, not bridge leftovers.

## Interaction model (post-fix, Sep 16 evening)
- **Why keys/clicks need the overlay:** CET routes mouse+keyboard into mod
  ImGui ONLY while the CET overlay is open (`D3D12::SetTrapInputInImGui` in
  Overlay.cpp); with the overlay closed there is no cursor and no key events
  (that's the "no mouse indicator" the user saw). So the terminal is:
  - **read-only display** when opened by hotkey while playing (hotkeys only
    fire with the overlay closed — CET wiki),
  - **fully interactive** (cursor, clicks, keys) the moment the overlay opens.
- `onOverlayOpen` → `terminal.onOverlayOpen()`: auto-shows the terminal
  (unless `[X]` suppressed it for this session; `suppressAuto` resets on
  overlay close). `onOverlayClose` keeps the screen up as read-only display.
- **v0.1.1 — TAB/panel navigation model (Sep 16, user-directed):** the
  earlier arrow-key model made Enter on a focused `<`/`>`/GO ImGui button
  re-trigger a chapter step (looked like a "flicker back to previous"), and
  the header title rendered the stale mid-load `M.data` for a frame. Both
  fixed:
  - `TAB` (or shift-TAB) cycles the focus ring BOOKS → VERSES → SEARCH →
    MEMORY → NOTES → ABOUT (`navGlobal`); arrows navigate within the focused
    panel (`navPanel`): BOOKS up/down + Enter/Right to open, VERSES
    up/down/pg/±10/home/end + left/right chapter, SEARCH & NOTES up/down +
    Enter to open. `1`-`5` still jump straight to a tab.
  - Chapter `<`/`>`/GO buttons, tab selectables, and every action button are
    now **mouse-only** (`theme.button… and ImGui.IsItemClicked(ImGuiMouseButton.Left)`),
    so keyboard Enter/Space can never fire them.
  - The browse header title is computed from `M.book`/`M.chapter` (the jump
    target, resolved against the books list) plus an explicit `LOADING N …`
    marker while the new chapter payload is in flight — no stale "previous
    chapter" flash.
  - Default glass lowered 55 → **45%** (and RESET target); live
    `exalted_settings.json` updated to 45.
  - ImGui bindings added to the verified set: `IsItemClicked(int mouse_button)`,
    `ImGuiMouseButton.Left`, `Tab`/`Shift` keys.
- Key handling is gated on `ImGui.IsAnyItemActive()` so arrow/tab/enter keys
  are not stolen while a text field (jump bar, search, notes) has focus.
- **Jump bar in the browse header:** `BOOK [name/short/number] CH [n] [GO]`
  (Enter commits via `IsItemDeactivatedAfterEdit`), replacing the old chapter
  GOTO field (`doJump`). No auto-jump while typing.
- **Glass opacity (`About` tab, persisted):** `theme.withAlpha` rewrites only
  the alpha (top) byte of a 0xFFRRGGBB color using integer arithmetic (no
  bitwise ops — safe on CET's LuaJIT). `theme.glass` default 45%, adjustable
  25-95% via `-`/`+`/`RESET`, stored in `exalted_settings.json`
  (`cache.getSetting`/`setSetting`). Child panels stack alpha by depth
  (`theme._depth`), so inner scroll panes read slightly darker than the
  window behind them. ImGui packed-color top byte == alpha is confirmed by
  `PushStyleColor(int idx, int col)` → `static_cast<ImU32>` in sol_imgui.
- ImGui bindings verified in this CET build: `IsKeyPressed(key[,repeat])`,
  `IsKeyDown`, `IsKeyPressed`, `ImGuiKey` enum (`new_enum`), `SetScrollHereY`,
  `IsItemDeactivatedAfterEdit`, `IsAnyItemActive`, `IsItemClicked(int)`,
  `ImGuiMouseButton.Left`.
